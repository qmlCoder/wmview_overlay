# overlay 分子对齐（使用说明）

把文件列表里**多选的分子**旋转/平移到与**参考分子**最接近，结果直接写回场景。
典型用途：同一系列的构象、优化结果、不同方法算出的同一分子做叠合比较。

## 界面

| 位置 | 含义 |
| --- | --- |
| 参考分子 | 文件列表里**单击**选中的分子（`wmapi_files.get_select()`），也是对齐的目标；必须已在场景中 |
| 待调节分子 | 文件列表里**Shift 点击**、多选开关或「全选/空选」标记的分子（`get_option()`）；面板里每个分子一行 |
| 选中原子 | 每行下面显示该分子当前选中的原子（1 起的编号，与场景里的原子标签一致） |
| 同步按钮 | 用参考分子选中的原子**同步**给所有待调节分子，见下 |
| 对齐指标 | RMSD / MESD 两种误差指标，原理与区别见同目录《对齐算法原理》 |
| 开始对齐 | 逐个对齐并写回场景 |
| 保存对齐结果（`-overlay.gjf`） | 把对齐过的待调节分子按当前场景坐标另存为独立 GJF，文件名是原名加 `-overlay`，详见下面「保存对齐结果」 |
| 插件文档 | 打开主程序「程序文档」并定位到本说明（旁边目录树里可切到《对齐算法原理》） |
| 日志 | 每一步的结果与误差，例如 `A.gjf -> B.gjf,rmsd(avg):0.0231` |

## 使用步骤

1. 在文件列表**单击**参考分子，让它显示在场景中。
2. 标记要调节的分子：按住 Shift 点击，或打开「多选」开关后逐个点击；也可以用「全选 / 空选」批量标记。
3. （可选，推荐）在场景里点选参考分子中要参与对齐的原子（比如某个环、某几个原子），
   然后点 **「同步原子选择到待调节分子」**，把同一套原子索引写给所有待调节分子。
4. 选择对齐指标（默认 **RMSD**）。
5. 点 **「开始对齐」**。
6. 需要留档就点 **「保存对齐结果」**，在分子目录里生成 `<原名>-overlay.gjf`。

## 保存对齐结果

点「保存对齐结果」会把分子各写成一个独立的 GJF 文件：

- **保存对象**：优先「本次会话里对齐过的分子」；如果还没对齐过，就是「当前的待调节分子」（按当前坐标保存，
  日志里会标注 `（当前坐标，未参与本次对齐）`）。
- 判定只要求**分子还在场景中**，**不跟着文件列表的选择变化**：单击某个分子把它变成参考分子、或改动多选列表，
  都不会让这个按钮失效。

- 位置：分子目录（文件列表面板顶部显示的那个目录）。
- 文件名：源文件名去掉扩展名后加后缀 `-overlay`，例如 `BTM-1_sp.gjf` → `BTM-1_sp-overlay.gjf`。
- 坐标：场景里的**当前坐标**（也就是对齐后的结果），单位 Å，保留 8 位小数。
- 头部信息：

  | 源文件类型 | 任务行（route） | 电荷 / 自旋 |
  | --- | --- | --- |
  | `.gjf` | 取源文件的任务行 | 取源文件的电荷 / 自旋 |
  | `.log` | 取源文件的任务行 | 源文件里没有这两个值，退回 `0 1` |
  | 其它（`.fch` / `.cub` / `.xyz` 等） | 退回默认 `opt freq b3lyp/6-31g` | 退回 `0 1` |

  凡是退回了默认值的情况，日志里都会有 `注意 xxx：…请检查` 的提示，请核对后再拿去计算。
- 同名文件会被**直接覆盖**，不会备份。
- 保存后的新文件不会立刻出现在文件列表里，点文件列表面板的 **↻ 刷新**按钮即可看到。

## 对齐时发生了什么

1. 还没进入场景的待调节分子会先 `wmapi_files.load_file(name, false)` **静默加载**：
   只加入场景，不切换当前显示的分子，也不改变文件列表的选择。
2. 取参与对齐的原子：**有选中原子就用选中的，否则用全部原子**。
3. 计算最优刚体变换（只旋转 + 平移，**不改键长、键角**）。
4. 通过 `wmapi_editor.set_atom_position(name, record)` 把新坐标写回场景中的分子。

## 注意事项

- **原子对应关系按下标一一对应**：参考分子选中的第 i 个原子 ↔ 该分子选中的第 i 个原子。
  所以两边选中的原子索引要一致（用「同步」按钮最省事）。
  如果不选任何原子，则按**全部原子**依次对应，这隐含要求两个文件里的原子顺序一致。
- 两边**选中的原子数不一致**时，该分子会被跳过（日志里会写明原因）。
- 只对齐**选中的原子子集**，没选中的原子不参与计算，自然不会贴合；想让整体都贴上来就不要选原子。
- MESD 会主动放弃个别偏差大的原子（详见《对齐算法原理》），看起来可能不如 RMSD 齐。
- 对齐结果只改场景坐标，**不会自动写文件**；要保存请用编辑器插件的保存 GJF。
- 场景里「建模」面板打开时，鼠标点击会被编辑器接管（这是主程序的交互约定），
  此时选原子请先切换到其它面板或清空建模片段框。

## 常见问题

**为什么有的分子没动？**

- 它是参考分子本身（不对齐自己）；
- 或者与参考分子选中的原子数不一致（日志会提示，可点「同步」按钮统一）；
- 或者没进入场景且加载失败（日志里会有 `加载 xxx 失败`，常见于多选里混进了 `.log` 这类非结构文件）。

**为什么个别原子对不上？**

- 用了 MESD（它不保证每个原子都贴合）；
- 或者只对齐了选中的子集；
- 或者两个分子本来就是不同构型 —— 刚体叠合无法消除构型差异。

**面板上的「选中原子」为什么变了？**

- 它读的是场景里该分子的真实选择状态；主程序切到「场景」面板时会清空所有分子的原子选择。

**点击保存后文件去哪了？**

- 写在分子目录里（文件名 `<原名>-overlay.gjf`）；文件列表不会自动刷新，点面板上的 ↻ 刷新即可看到。
- 如果日志里出现 `注意 xxx：源文件取不到完整的任务信息…`，说明任务行或电荷/自旋用了默认值，请打开文件核对。

## 依赖的宿主 API

| API | 用途 |
| --- | --- |
| `wmapi_files.get_select / get_option / on_select / on_option` | 获取参考分子与待调节分子列表、订阅变化 |
| `wmapi_files.get_mole_info / load_file` | 读取分子结构、静默加载进场景 |
| `wmapi_scene.get_mole_geom / get_atom_select / set_atom_select / on_atom_select` | 读取几何与原子选择、写入原子选择、订阅选择变化 |
| `wmapi_editor.set_atom_position` | 把对齐后的坐标写回场景 |
| `wmapi_cores.add_appdoc / notify / add_logText / get_show_siders` | 注册本文档、提示与日志、判断面板是否显示 |

## 脚本 / AI 调用（wmapi_overlay）

本插件也把主要功能暴露成脚本 API（挂在 `window.wmapi_overlay`），与面板按钮等价，面板没打开也能调用，
写在脚本面板里执行或交给 AI 助手都行：

| API | 作用 |
| --- | --- |
| `align(method?)` | 对齐（`'rmsd'` / `'mesd'`，缺省用面板当前选择），返回每个分子的误差与状态 |
| `sync_selects()` | 把参考分子选中的原子同步给所有待调节分子 |
| `save(suffix?)` | 另存为 `<原名><suffix>.gjf`（缺省 `-overlay`），返回写出的文件路径 |
| `get_state()` | 读取当前状态（参考分子、待调节分子、各自选中的原子、已对齐的分子） |
| `set_method(method)` | 切换对齐指标（面板上的单选会同步变化） |

完整签名与参数说明见脚本面板「参考」页里的 overlay 标签，也可以用 `wmapi_script.get_apidoc('overlay')` 取原文。
